2. 部署过程

MOSS-TTS-Nano

环境搭建
通过 Homebrew 安装 openfst 1.8.4，从源码编译 pynini 2.1.7，耗时约 2 分钟
依赖安装
PyTorch 2.7.0 + transformers + WeTextProcessing（需跳过依赖冲突），venv 共 649MB
模型下载
ONNX TTS + 音频分词器，两次分别下载，第二次需手动补全，共 728MB
服务启动
首次启动耗时较长（WeTextProcessing 预热 + ONNX 模型加载），约 30s
综合难度
较复杂 pynini 编译、依赖冲突、模型下载不完整等问题需逐一排查

Qwen3-TTS MLX

环境搭建
创建 Python 3.12 venv，无需编译任何 C 扩展
依赖安装
pip install mlx-audio 一行完成主依赖，额外安装 ffmpeg（brew）
模型下载
一次性下载 2.9GB MLX 8-bit 模型，约 7 分钟（取决于网速）
服务启动
uvicorn 秒级启动，模型懒加载（首次请求时载入约 8s，之后常驻内存）
综合难度
较简单 仅需处理 webrtcvad 的 pkg_resources 兼容问题和 ffmpeg PATH 配置

4. 推理性能测试

测试环境：Mac Mini Apple Silicon，16GB 统一内存，无 GPU 独显，两者均为热启动（模型已在内存中）。

测试用例 MOSS-TTS-Nano Qwen3-TTS MLX 音频时长 优势方
短句中文（约 16 字） ~3.0s 2.86s 3.34s 新 ↑
短句英文（约 9 词） ~2.9s 2.31s 2.86s 新 ↑
长句中文（约 42 字） ~10s 7.16s 10.06s 新 ↑
冷启动（首次加载模型） ~30s ~8s — 新 ↑
RTF（实时倍率） ~0.6x（CPU） 0.71~0.86x（GPU） — 相近

RTF 说明

RTF（Real-Time Factor）= 推理时间 / 音频时长。RTF < 1 表示快于实时，数值越小越快。两者均已达到实时可用标准。MOSS-TTS-Nano 的 RTF 看似更低，是因为其输出音频更短（推理量少），实际上两者推理速度相近，Qwen3-TTS 在长文本上优势更明显。

6. 综合评分

💾
内存效率
Qwen3-TTS 仅占 1.66GB，比 MOSS 节省 70%，16GB 机器余量更充裕
🎯
音质与表现力
1.7B 参数 vs 0.1B，Qwen3 音质、韵律、自然度均有质的提升
🔌
接口兼容性
OpenAI 兼容格式，现有 openai SDK 代码改一行 base_url 即可接入
⚡
推理速度
MLX GPU 加速，长文本比 ONNX CPU 快约 30%，RTF 均 < 1x
💿
磁盘占用
Qwen3 模型更大（2.9GB vs 728MB），但 SSD 空间通常不是瓶颈
🖥️
Web UI
MOSS 内置完整 Playground 界面；Qwen3 需单独启动 Node 前端

7. 结论与建议

整体推荐：Qwen3-TTS 1.7B MLX ✅

在当前 Mac Mini（Apple Silicon，16GB）硬件环境下，Qwen3-TTS MLX 版本在内存占用、音质表现、接口兼容性三个最重要维度上均优于 MOSS-TTS-Nano，同时推理速度持平或略优。唯一的短板是缺少内置 Web UI，但对于以 API 调用为主的场景影响有限。

如后续需要进一步提升：可考虑换用 0.6B 版本（内存降至 ~1GB，速度快于实时）以降低延迟；或开启 VoiceDesign 变体探索更丰富的音色设计能力。
